# Formal V1 Matchup Matrix (Phases 7-10)

Agents: `random_agent` (official template), `abomasnow_corrected` (Mega Abomasnow
ex, `decks/abomasnow_ex_corrected_v1.csv` — see `results/abomasnow_deck_audit.md`),
`dragapult_agent` (**label used in this run's raw data == the Phase-4
`dragapult_fix_v1` variant, `src/agents/dragapult_agent_always_first.py`, NOT the
original `src/agents/dragapult_agent.py` — flagged clearly here since the raw CSV
reuses the bare name**), `iono_agent` (Iono's), `lucario_ex_agent` (Mega Lucario
ex). 500 games per pairing, 10 unique pairings, 5000 games total, zero aborted,
generated by `tools/round_robin.py`. Raw per-game data:
`results/formal_matrix_v1/*/games/*.jsonl` (never deleted/overwritten).

500/matchup (not 1000) was used for this phase per the prompt's own fallback
clause ("if computational cost unexpectedly becomes significant, use 500 games per
matchup but explain the tradeoff") — 5000 games already took several minutes of
wall-clock even on this fast native engine, and the per-pairing significance tests
below already resolve cleanly at n=500-1500 (see Phase 9), so the extra
statistical power from 1000/matchup was judged not worth roughly doubling the
runtime at this point in a 6-day-deadline project. This can be revisited later if
finer-grained distinctions (e.g. Dragapult vs. Lucario, currently a statistical
tie) become decision-relevant.

## Phase 9 — statistical analysis (agent-vs-agent pool only, random excluded)

Aggregate win rate per agent across its 3 agent-vs-agent matchups (`tools/
stats.py`, Wald 95% CI):

| Agent | Aggregate W/L | Win rate | 95% CI |
|---|---|---|---|
| lucario_ex_agent | 884/1500 | 58.93% | [56.4%, 61.4%] |
| dragapult_fix_v1 | 863/1500 | 57.53% | [55.0%, 60.0%] |
| iono_agent | 680/1500 | 45.33% | [42.8%, 47.9%] |
| abomasnow_corrected | 573/1500 | 38.20% | [35.7%, 40.7%] |

Pairwise two-proportion z-tests on the aggregate rates:

| Comparison | z | Significant (|z|>1.96)? |
|---|---|---|
| lucario vs dragapult_fix_v1 | -0.78 | **no** — statistical tie |
| dragapult_fix_v1 vs iono | -6.68 | yes |
| lucario vs iono | -7.46 | yes |
| iono vs abomasnow | -3.96 | yes |
| dragapult_fix_v1 vs abomasnow | -10.60 | yes |
| lucario vs abomasnow | -11.36 | yes |
| head-to-head dragapult_fix_v1 vs lucario (n=500, not aggregate) | -1.77 | no — also a tie |

**RESULT**: a clean, statistically supported 3-tier structure: **{dragapult_fix_v1,
lucario_ex_agent} are statistically tied for best** (neither the aggregate
difference nor their direct head-to-head reaches significance), **iono_agent is a
significant step below both**, and **abomasnow_corrected is significantly weakest
of the four**. This is NOT a simple transitive ranking by raw win rate alone,
though — see the non-transitivity note below.

**HYPOTHESIS/RESULT (non-transitivity)**: the aggregate ranking (Lucario
58.9% > Dragapult 57.5%) is not fully consistent with head-to-head play, where
Dragapult_fix_v1 beats Lucario 52.8%-47.2% (itself not significant, n=500).
Lucario's slightly higher aggregate comes from crushing Iono far harder (78.2%)
than Dragapult does (65.4%), while both beat Abomasnow by similar margins
(51.4% vs. 54.4%). This is a real example of why "best agent" isn't reducible to
a single scalar in a non-transitive local metagame, and why the full head-to-head
matrix (not just an aggregate average) is the primary deliverable, per the
prompt's own instruction ("do not rank agents only by win rate against Random...
the important information is the cross-matchup matrix").

## Phase 10 — best current baseline

**Best agent (this local 4-deck pool, NOT a claim about the real competition
meta — see caveat below)**: `dragapult_agent_always_first`
(dragapult_fix_v1) and `lucario_ex_agent` are **statistically tied for best**.
Dragapult_fix_v1 is recommended as the practical default going forward because
(a) it beats every other deck in the pool including Lucario in raw head-to-head
count (264/500, though not significantly), (b) it is a smaller, better-understood
change from a well-audited baseline (Phase 1-4), and (c) `docs/environment.md`'s
corrected first-player mechanics apply most directly to it. This is a judgment
call given the statistical tie, not a claim that Lucario is worse — both should be
considered live candidates for the Simulation submission.

**Best deck vs. best agent, kept conceptually separate per the prompt's
instruction**: the "deck" question here is really "which of the two decks
authored by these agents (Dragapult ex, Mega Lucario ex) is stronger" — since
each agent module is tightly coupled to its own deck's card IDs (the heuristics
are deck-specific, not a general-purpose engine that could be pointed at an
arbitrary decklist), agent and deck are not independently swappable in the
current architecture. `src/agents/common.py`'s shared helpers and each agent's
explicit `--deck-a`/`--deck-b` override support in `tools/tournament.py` (used
already in Phase 5 for the Abomasnow correction) DO preserve the capability to
test deck variations against a FIXED heuristic in future work (e.g. a modified
Abomasnow decklist against the same `abomasnow_agent.py` scoring code) — that
capability is intentionally preserved, not exercised further this phase per the
prompt's explicit instruction not to launch a full deck-optimization project yet.

**Caveat (explicit, per the prompt's anti-overfitting instruction)**: this
ranking describes which of *these four locally-ported, official-notebook-derived
heuristic decks* performed best against *each other* in *this local 5000-game
benchmark*. It is not a claim about the real Kaggle Simulation ladder's
competitive meta, which may contain entirely different decks, strategies, and
opponent skill levels this local pool cannot represent.
