# V17 Roadmap — консолидированный список реализации

Составлен 2026-08-15 (до дедлайна Simulation ~40ч; игры идут ещё ~2 недели после).
Контекст: V17 (margin 0.20 + 1500ms) сабмичен; локально ≈ V6 (47%), победа над V12 12:8.
Эмпирика: удвоение бюджета симуляций НЕ меняет винрейт → узкое место = качество оценки
и модель скрытой информации, НЕ скорость.

## Блок A — до дедлайна (реализуемо, по приоритету)

### A1. Детерминизация по архетипу оппонента + учёт его дискарда
- **Что**: классифицировать архетип оппонента по видимому борду
  (`src/meta_analysis/archetype_signatures.py`), сэмплировать его скрытые зоны из
  реального канонического декл-листа архетипа (реплей-данные, уже в repo) минус
  видимый борд минус его дискард (новые поля ABI: opp_deck_guess[], opp_discard[]).
- **Файлы**: `native_bridge.py` (классификация + новые поля), `v17_abi.h`,
  `observation.hpp`, `mcts.hpp::sample_opponent_hidden()`.
- **Оценка/риск**: ~4–6ч; умеренный (изменение ABI).
- **Как мерить**: НЕ через vs-V6 (там зеркало уже верно) — через мета-гаунтлет
  (базлайн: Kangaskhan 9/20, Fezandipiti 17/20, Grimmsnarl 18/20) и ладдер.
- Покрывает предложение «PIMC» (оставшиеся 20%: вероятностный пул).

### A2. Микро-чек леталя в свой ход (опционально, после A1)
- **Что**: перед MCTS перебрать цепочки СВОИХ решений до конца текущего хода
  (search_step-enumeration, вся информация видима) — если найден гарантированный
  добор последних призов, играть его без поиска. ~10–20мс.
- **Оценка/риск**: ~2–3ч; низкий.
- **Замечание**: покрытие уже близко к полному (терминальный +1 насыщает mean → MCTS
  выбирает выигрыш в 1 ход надёжно; V6-план даёт 50000 летальному добору) — делать
  только при запасе времени, эффект ожидается малым.

### A3. Тюнинг после A1 (только если гаунтлет покажет сдвиг)
- margin 0.15/0.20/0.25 × num_determinizations 4/6/8 — по 60 игр, выбрать по сумме
  (гаунтлет-дельты важнее vs-V6).

## Блок B — после дедлайна (исследовательское)

### B1. Обученная value-функция P(win) в статических C++ массивах
- **Что**: обучающая выборка «состояние → исход» из 1040 локальных сырых эпизодов
  (`data/episode_sample/`, ~100К пар; при необходимости догрузить точечно по
  manifest'ам); XGBoost/маленький MLP; экспорт деревьев/весов в C++ массивы +
  крошечный евалуатор (без ML-библиотек, без Python в роллаутах).
- **Оценка/риск**: ~12–20ч; ВЫСОКИЙ (V16 с более слабой XGBoost-интеграцией дал те
  же 45% — модель может не побить ручную эвристику V6).
- **Подготовка данных безрисковая** — можно начинать в любой момент, пригодится и
  для Strategy-трека (дедлайн 2026-09-13).
- Покрывает предложение «NNUE» по сути; NNUE-механика (инкрементальные апдейты,
  int8+SIMD) НЕ нужна: оценка вызывается ~2К раз/решение, микросекунды на фоне
  миллисекундных SearchStep.

### B2. PUCT вместо чистого UCB1
- V6 greedy-скор как prior: `c · prior · √N/(1+n)` — исследование тратится на
  осмысленные ходы. Малый диф в `mcts.hpp`. Имеет смысл ПОСЛЕ B1 (prior от
  обученной модели ещё лучше).

### B3. Голосование детерминизаций (Ensemble-UCT)
- Выбирать кандидата, выигрывающего ранжирование в большинстве миров, вместо
  пула средних. Устойчивее к одному «испорченному» миру.

### B4. Глубокое дерево (информационные множества)
- Только после B1 (пока оценка = V6, глубина бессмысленна — доказано ночными
  прогонами). Неделя+ работы. Тогда же станет актуальна transposition table
  (Zobrist) — до этого TT неприменима (одноуровневое дерево, линейные роллауты,
  переходы внутри чужой DLL некэшируемы).

## Отклонено (с обоснованием)

- **Bitboards / свой движок симуляций**: симуляции исполняет официальная
  précompiled cg.dll (лицензия competition-use-only; свой клон правил = недели +
  риск расхождения + лицензионный вопрос, см. cg_engine.hpp). Плюс эмпирика:
  больше роллаутов той же оценки ≠ сильнее.
- **Zobrist/TT сейчас**: см. B4.
- **Alpha-beta «форсированный мат в 3–5 полуходов»**: под скрытой рукой оппонента
  гарантий не даёт (его ответы включают неизвестные карты); честная версия = A2
  (леталь в пределах своего хода, где информация полна).

## Решения по дедлайну (напоминание)

- Порог: V17 (или вариант) должен обогнать замороженные 669.6 (V12), иначе пара
  V6 (683.7) + V12 (669.6).
